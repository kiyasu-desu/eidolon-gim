# 现实中的唱片和演出算作角色自己的经历，声优只作系统内部数据

角色是 283 事务所的偶像、用户是她的制作人，这是整个系统的视角。但原作本身会把现实中的 CD 发售和 live 当作戏里的事来办，所以我们把它们也纳入戏里：现实中发售的唱片就是她们发行的唱片，现实中的 live 就是她们站上的舞台。角色知道名称、日期、会场、出演者、曲目单这些可以查证的事实，但不知道台上具体发生了什么，也不编造。哪些演出算她上过，按她的声优实际出演的场次判断，所以系统需要声优数据；但角色本人不知道自己有声优，界面上也不展示。否则「是我站上了舞台」和「是我的声优站上了舞台」会互相矛盾。

系统不接搜索，角色只能靠我们提供的资料说出这些事实，所以资料的准确性就是防幻觉的底线：以官方来源为准；官方没有集中公布的（逐日出演者、缺席），只采用附有官方新闻链接的粉丝整理；由导入命令生成资料文件，人工审核 diff 后提交，不做定期自动抓取，因为没人看过的数据会直接变成角色的「记忆」。资料里查不到的，角色老实说想不起来，既不否认也不附和。

## Considered Options

- **完全在戏里，现实信息一律不收**：视角最干净，但原作本身就在戏里办发售纪念和 live 纪念，角色对这些一无所知反而不像本人。
- **角色知道自己是游戏角色、可以谈论声优**：拆掉了「制作人」这层身份。
- **按公告的出演组合判断她上过哪些演出**：不需要声优数据，但角色会声称自己上了实际没上的舞台。

## Consequences

- 资料有截止日：已公布但延期、取消的演出，要重新导入才会更正。
- 实体周边不收录；只有闪耀色彩的偶像演唱、发售过的才算她的歌曲，演出曲目单里翻唱的其他品牌歌曲照实记录，但不算她的歌曲。

## 修订（2026-09-28）：演唱者由 ふじわらはじめ 补齐，不用 imas-db

spec 原先定的是由 imas-db 补齐 Lantis（官方）缺少的唱片资料。实现 ticket 03 时实测，imas-db 的歌曲和唱片资料库没有闪耀色彩（只收到 2017 年前后的 765 系），闪耀色彩只有公演曲目单页。所以补齐演唱者改用粉丝整理的 ふじわらはじめ 的 API（`api.fujiwarahaji.me/v4`，按唱片列出每首的演唱者，CC BY-NC 4.0）。Lantis 有几十首曲目没写演唱者，不补齐这些歌就不进资料；而演唱者没有别的官方来源可查，所以接受粉丝来源，但只用在官方空缺的地方，并且逐条交给人核对。

- 它只补 Lantis 没写的演唱者：Lantis 曲目没写演唱者，或者只写了特别组合名、没写是哪几位偶像（这个名字得是全体、Lantis 在别的页面上列出过成员的特别组合，或者 ふじわらはじめ 也写着同一个组合名，才采用）。Lantis 写了的以 Lantis 为准；Lantis 写的演唱者对不上偶像名单时，不拿 ふじわらはじめ 的说法覆盖，这首列进导入报告、不写入。
- 两边对不上的地方按 Lantis 写入，列进导入报告。
- 由它补齐的每一首都列进导入报告，来源里记着 ふじわらはじめ 的唱片页，供人工核对。
- 逐日曲目单仍然按原计划取 imas-db 的公演页。

## 修订（2026-09-28）：演出列表由 wikiwiki 判断哪些是演出，早期场次取旧官方站

实现 ticket 04 时实测（`.scratch/world-knowledge/research/lives-sources.md`），官方门户 CMS 的 `LIVE-EVENT` 分类不够当演出列表用：它从 2020-09 才开始收录，1stLIVE 等早期场次都没有；里面还混着酒店合作、展览、检定考试、电视节目，没有字段能和演出区分开。所以演出列表改为：

- 官方来源有两个：CMS，和 CMS 之前的旧官方站（`idolmaster.jp/event/{年}.php`）。名称、演出日和会场只取官方的。
- 官方条目只有在 wikiwiki 同一天也有闪耀色彩的演出时才收录。靠粉丝来源判断「这是不是一场演出」，是因为没有别的办法；但粉丝来源不能让一场演出凭空出现：wikiwiki 有、官方列表里没有的，只列进导入报告。
- 旧站列着所有品牌的活动，所以旧站的条目除了日期对得上，名称也要相近，而且 CMS 已经对上的那场 wiki 演出不再对旧站条目（旧站上延期前的原定日期不会多出一场）。
- wikiwiki 标明中止或没有出演的演出不收录，列进报告。
- 后果：收不收一场演出，取决于官方列表有没有它。其他品牌或外部主办的活动上的嘉宾出演（アニサマ、TIF、リスアニ 等），官方门户把它登记成闪耀色彩的演出的就收，没登记的只进报告；已经公布、但官方列表还没收录的场次（2026-09-28 导入时的 noctchill 公演）也要等收录后重新导入才有。这和「已经公布的演出同样收录」有出入，我们接受：宁可让角色暂时想不起一场演出，也不让没有官方依据的条目进资料。
- wikiwiki 写错或没写的出演者（例如延期公演只留着延期前的旧名单），由人查证后写进资料文件旁边的 `world-corrections.json`：指定某个演出日实际是谁出演（附出处和说明），以及哪些出演者不是偶像（主持人等）。Lantis 和 ふじわらはじめ 都没写、或写的是跨品牌组合的曲目，也在这里按品番和曲目序号写明演唱的偶像（和特别组合名），或者注明不算歌曲（伴奏、Non-Stop Remix）；曲名也一起写上，唱片重新排了序号时这条更正就不再套用，列进报告。每次导入都套用，导入报告列出套用了哪些、哪些对不上任何演出日。这是人工审核的延续：更正和资料文件一样提交进仓库，由人负责。
- 她以角色本人的名义出演、声优不在场的（ORCHESTRA CONCERT 2022 上，屏幕里的大崎甘奈配着录好的歌声演唱），也算她上过的演出，和 xR 演出一样。「声优实际出演才算」原本是为了不让角色声称上了没上的舞台；以角色名义出演时，在戏里上台的就是她本人。

## 修订（2026-09-28）：一天两场的演出日不写曲目单

实现 ticket 06 时实测（`.scratch/world-knowledge/research/setlists-source.md`），imas-db 的公演页是按「场」列曲目单的，不是按演出日：SUMMER PARTY 2019、LME、Uka、ORCHESTRA CONCERT 2025、騎士団のヴェール、XXX 都有一天昼夜两场、曲目不同的日子。资料按演出日记，所以：

- 一个演出日只有 imas-db 上正好一场公演落在这一天时，才写入这场的曲目单；一天两场的不写，列进导入报告，不挑其中一场、也不把两场拼在一起。标着「全公演共通」的表算每一天各一场。
- 后果：这 8 个演出日（2026-09-28）角色查不到曲目单，只能说想不起来。宁可想不起来，也不把另一场的曲目说成她那天唱的。要补上，得把资料改成一个演出日可以有几场，另开 ticket。
- 曲目单里点名的偶像不在那天的出演偶像里时（出演者来自 wikiwiki，异次元フェス 那两天明显不全），不写她，列进报告；由人更正出演者（`world-corrections.json`）后重新导入。
