# 落地页是独立于「制作人的手机」的视觉世界

访客打开网站第一眼看到的落地页，要做到 Awwwards / FWA / CSSDA 每日最佳的水准：实验性排版、滚动驱动的叙事、实时渲染的光。这在 DESIGN.md 那套中性灰白、扁平克制的「制作人的手机」里做不出来。所以落地页自成一个视觉世界：永远深色，以「棱镜分光」为主线（一束白光散成 28 道印象色，每道是一位偶像），有自己的字体、动效和版式；DESIGN.md 和 shadcn 纪律只管落地页里的登录面板和行动按钮。唯一沿用的是印象色规则：属于她的颜色只用官方印象色，不另取。两个世界在最后一幕接上：光汇聚成一块手机屏幕的白光，转进应用。

## Considered Options

- **留在 DESIGN.md 里，只把动效做到极致**：视觉统一、维护一套规范，但中性外框和扁平原则本身就排除了这个水准需要的东西。
- **整个应用都换成落地页的风格**：应用的原则是「角色在前，系统在后」，对话、设置、后台都要安静，不适合实时光效和实验排版。

## Consequences

- 落地页的依赖（Lenis、OGL）和展示字体只在落地页的路由里加载，不进应用的包。字体按落地页实际用字在构建时做子集。
- 落地页不跟随系统的浅色、深色，永远深色。
- 风格可以向原作官方站靠拢，不把「撞脸」当约束；但不使用官方 logo、组合 logo 等商标，组合名一律用文字排出来。非官方声明在首屏和页脚都要有。
- 已登录的用户打开 `/` 直接进入对话列表（对话列表从 `/` 搬到 `/conversations`），落地页只是访客的门面；登录面板在落地页里弹出，`/login` 保留给登录被拒的回跳和开发登录。
- 设计依据见 `docs/research/landing-page-references.md`。

## 修订（2026-10-10）：落地页有自己的根 layout，字体自托管子集

原型（`prototype/landing-page` 分支的 `3d07693`）测出：落地页挂在应用的根 layout 下时，next/font/google 为 CJK 字体生成的切片 CSS 约 500 KB，会阻塞渲染，手机 4G 下 LCP 是 4.9 秒；拦掉这些 CSS 后只有 0.86 秒。所以：

- 落地页用路由组拆出**自己的根 layout**，不加载应用根 layout 里的字体。在两个根 layout 之间跳转是整页加载，从落地页进应用本来就要经过登录或「继续」，可以接受。
- 落地页的字体（Shippori Mincho B1、Noto Serif SC、Noto Sans SC）在构建时按落地页实际用字做静态子集、自托管，**不用 next/font/google 加载 CJK 字体**。
- 性能预算的口径改成「落地页自身的首屏 JS 压缩后不超过 50 KB，不含框架基线」。Next 16 + React 19 每页本来就有约 161 KB，原来「整页首屏 JS ≤ 150 KB」的写法做不到。手机 4G 下 LCP ≤ 2.5 秒不变。

## 修订（2026-10-12）：第 4 幕加一台 three.js 画的手机，用第三方模型

「着信」重做成一台实体的手机：她的光收成手机的侧边，手机随滚动转过背面、转到正面，亮屏来电（`.scratch/landing-call-phone`）。所以：

- 落地页多一个依赖 **three.js**，只用 WebGL 渲染器。和光层（OGL）一样打成单独的包，只在运动档、滚到第 3 幕附近时才动态加载，**不算首屏**。手机是一块单独的画布，叠在光层上面，只在画面有变化时画，离开这一段就不画，手机上离开时释放上下文。
- **不用 WebGPU**：这一节的开销不在 GPU 算力，一台手机几万个顶点 WebGL 足够；WebGPU 的包更大、第一次编译着色器更慢，iOS Safari 和旧安卓还要回退到 WebGL，等于两套都要维护。
- 手机模型用第三方的 **Sketchfab 上 Ranguel 的「iPhone 17 Pro」（CC BY 4.0）**，改成 18 Pro 的银色、压缩到约 1 MB，放在前端静态目录，旁边的 CREDITS 写明出处、授权和改动；页面上不放署名，文字里不出现产品名。压缩只做量化，不用 meshopt、Draco 这类要在浏览器里跑 WebAssembly 解码的压缩，贴图也不打进 GLB（three.js 要经 blob: 地址去取）：站点的 CSP（ADR-0017）这两样都不放行，为一台展示用的手机放宽全站的 CSP 不值得。
- 预算口径不变：落地页自身的首屏 JS 压缩后不超过 50 KB，不含框架基线；three.js 和模型不算首屏，验收脚本另外报它们的大小。
- 手机画布丢了 WebGL 上下文时只换掉手机，不连带整个落地页降档。

## 修订（2026-10-16）：第 5 幕是一块 three.js 画布和体素小人

「记忆」重做成 3D 的纪念碑谷式场景：夜空里四座浮岛，几位偶像做成体素小人站在上面，镜头随滚动推近、拉远、转向（`.scratch/landing-memory-3d`）。原来的光路弧线、光点和指针痕迹删掉，光层（OGL）在第 5 幕不再画这一幕的东西：她们的光在第 4 幕末尾收掉，第 5 幕是 3D 画布自己的夜空。所以：

- 第 5 幕是**又一块单独的 three.js 画布**（WebGL 渲染器），和第 4 幕的手机一样只在运动档加载：滚到第 5 幕前约一屏时才动态下载场景代码、几位演员的体素文件，建画布；离开第 5 幕那一段就不画，手指操作的设备上离开时释放 WebGL 上下文、回来重建。**three.js 和手机共用一个包**，场景代码单独打包，都不算首屏。
- 画布固定铺满视口，叠在光层上面、这一幕的文字下面；镜头和画布的淡入淡出由落地页模型给（投影是模型里的纯函数，3D 层和 DOM 上要跟着场景走的东西同一个出处）。
- 体素小人从角色接口给的地址（存储桶的 `landing-voxels/`，ADR-0003 的修订）下载，每人露在外面的面合成一份网格，不用一个方块一个实例。地址没有或加载失败时，她站的地方是她印象色的方块加名字。
- 画布丢了上下文或建不起来时只收起这块画布，**不连带落地页降档**（静止图见 `.scratch/landing-memory-3d` 的票 06）。按帧降档照旧，这块画布画着的时候也量帧耗时。
- 预算口径不变：落地页自身的首屏 JS 压缩后不超过 50 KB，不含框架基线；第 5 幕的场景代码和体素文件不算首屏，验收脚本另外报它们的大小。
