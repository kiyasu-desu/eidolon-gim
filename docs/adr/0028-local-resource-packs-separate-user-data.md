# 本地剧情库与用户数据分库存放，立绘和剧情可独立停用

剧情及其向量属于可卸载资源，账户、对话、用户记忆属于需要保留的用户数据，因此运行时与重新向量化分别选择两个数据库路径。剧情包缺失或关闭时不自动回读旧应用库，也不关闭用户记忆检索；原生立绘采用可选本地资源根目录，关闭时同时停止提供模型文件接口。开关通过本地配置并在重启后生效。

旧共库数据用显式 `story migrate` 迁移：保留源库、先做一致性备份，只复制四张剧情表并核对分类及原始向量，不重新付费向量化，不删除用户数据，不覆盖不同的目标包。源库中的旧剧情副本保留作回退；后续导入只写独立库。相比自动改写或删除旧库，这会暂时保留一份旧副本，但使首次切换和撤回都可检查，避免卸载资源时误删用户历史。导入工具也拒绝把包含用户／其他应用表的数据库当成剧情包。
